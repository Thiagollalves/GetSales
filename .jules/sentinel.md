## 2024-05-18 - Fix SSRF and Injection risks in WhatsApp API
**Vulnerability:** The WhatsApp send API endpoint (`/api/whatsapp/send`) used unsanitized user inputs (`phoneId`, `apiVersion`) directly in a server-to-server `fetch` URL, creating an SSRF (Server-Side Request Forgery) and Path Traversal risk. Additionally, `token` and `phone` inputs were used directly in HTTP Headers and payload without validation, enabling Header Injection and malformed payload attacks.
**Learning:** External API wrappers must validate and strictly format all user-provided variables used in constructing URLs, headers, and payloads for downstream services. Even internal-facing tools shouldn't trust parameters blindly.
**Prevention:** Always validate parameter formats (e.g., using RegEx for digits `^\d+$` for IDs) before appending them to URLs. Validate tokens for newline characters `[\r\n]` to prevent header injection. Use tools like `zod` for robust input schema validation when possible.
