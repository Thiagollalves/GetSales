## 2025-05-18 - Open Relay Vulnerability in WhatsApp Send Endpoint
**Vulnerability:** The `/api/whatsapp/send` proxy endpoint fell back to using the server's `META_WHATSAPP_TOKEN` environment variable if the client did not provide a token. Without authentication on this fallback path, an unauthenticated client could use the server's Meta token to send arbitrary WhatsApp messages (Open Relay / SSRF risk).
**Learning:** Any backend proxy endpoint that uses server-stored API credentials must explicitly authenticate the incoming request. If the endpoint is intended to be called by both authenticated clients (providing their own token) and internal/webhook mechanisms (relying on server token), the latter must be guarded by an environment-based secret (e.g., `API_SECRET`).
**Prevention:** Always require an `API_SECRET` validation when a request relies on server-stored credentials. Ensure the service fails securely (returns 500) if the `API_SECRET` is missing in the server configuration, preventing a "fail open" scenario.
