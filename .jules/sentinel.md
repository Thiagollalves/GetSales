## 2024-09-08 - [SSRF & Path Traversal via Unvalidated API Proxy Inputs]
**Vulnerability:** The WhatsApp send API endpoint `app/api/whatsapp/send/route.ts` directly interpolates user-provided `phoneId` into a Facebook Graph API URL without validation. Additionally, the `phone` variable is passed unvalidated into the API payload. This could allow Server-Side Request Forgery (SSRF) and path traversal if malicious characters like `../` or query parameters were injected into `phoneId`, potentially redirecting the backend request to unintended endpoints or reading local configuration.
**Learning:** Backend proxy endpoints that forward requests to third-party APIs often implicitly trust user inputs when constructing URLs. Because these endpoints are often invoked directly by the frontend, inputs are entirely user-controlled and untrusted.
**Prevention:** Always validate, sanitize, and strictly type variables used in URL interpolation and backend proxy payloads. For IDs (like WhatsApp phone IDs), use strong regex validation (e.g., `/^\d+$/`) and ensure the backend fails securely with a 400 response if validation fails.
